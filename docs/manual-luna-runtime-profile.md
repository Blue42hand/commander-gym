# Protected manual Luna runtime proposal

This source support does not install or activate a service. The existing keyless
feeder remains the live deployment. Manual paid-capable runtime activation needs
its own exact protected profile, immutable artifact inventories, fresh synthetic
qualification, source CI and separately approved activation receipt. QA profiles
can never activate, regardless of their receipt fields. No automatic game starts,
provider validation call, budget/game cap, account or Redis service is added.

`manual_runtime_profile` defines the complete runtime identity. The identity seals
matched server/embedded adapter/frontend, sidecar and recorder source, launcher,
Python/JDK/SDK dependency tree and wheel files, service/proxy configuration, catalog,
and the unchanged legacy native/source helper closures. The existing acknowledged-incomplete registry is separately checksum-bound; no
original or disposition is copied into a public artifact. Every file and directory
is checked for nonsymlink custody; unindexed files reject. Production artifacts
are root-owned content-addressed directories. No secret value enters a profile,
argument, receipt, public log or Git artifact. The recording pins truthfully declare
paid capability and the selected model; actual deck/RNG evidence comes from native
initialization. This does not claim canonical recording or replay completeness.

The original approved private catalog is preserved. The activation proposal makes
a byte-identical immutable copy at `/srv/argentum-luna/artifacts/catalog/<digest>`,
root-owned, directories0750/files0640 with commander-prod group. The recorder runs
as the existing argentum-play UID with primary commander-prod group and existing
argentum-play supplementary group, so it can read the sealed registry and original
recording disposition. The provider process runs as commander-prod, cannot write
the copied catalog and cannot read native journals. The provider source remains
owner-only0600 under owner-only0700 parents; recorder group membership grants no
access to that file. No new account or group is created by this source.

## Credential boundary and one recorder

Root validates exact all-artifact/CI/qualification/approval/previous-runtime/sequence
before any service effects or systemd credential materialization. A root-owned
boot-specific attestation is required by fixed service launchers. On cold boot the
preflight takes the same rollout lock; when promotion already holds that lock,
preflight fully rechecks the existing attested bundle without reacquiring it.
Sidecar launch additionally checks its own sealed byte/dependency/catalog closure,
interpreter/stdlib and installed SDK metadata before reading credential copies.

Only the private sidecar unit receives the existing `openai.env`. Native and sidecar
receive a separately proposed private callback bearer through systemd credentials;
native reads its named Spring configtree, never a token value in argv/environment.
No bearer exists or is generated by these scripts. Recorder receives only nonsecret
profile context. Both the public LAN certificate and private LAN TLS key are delivered
to the proxy as credentials, preserving the root-only configuration directory.

The existing `NativeGameCapture` is composed with the merged `RecorderBridge` and
`RecordingHealthReporter`; reporter.tick owns scanning. There is no second capture
scanner/finalizer in the provider sidecar. Bridge starts before reporter; cleanup
stops reporter, bridge and capture in that order, attempting every close even if an
earlier close fails. IPC directory is native-UID-owned0750 with commander-prod group,
native.sock0600 and sidecar.sock0660. Actual peer UIDs must differ in deployment.
Native receives `commander-gym.recorder.socket`; sidecar receives only the remote
socket/nativeUID, with no native recording root/pins/lifecycle environment.

## Transactions, timers and conservative holds

The root dispatcher keeps one rollout lock across current-profile checks and legacy
keyless delegation. Source feeder has its own additional existing lock. Neither old
helper directory nor its indexed hash closure is edited. Proposed drop-ins route
updater, admission and source feeder through the profile-aware dispatcher. When
manual mode is active, automated keyless source/promotion work holds; its schedules
remain configured. New manual promotion always requires an exact new approval.

Promotion requires fresh exact healthy idle counters, closes admission and waits
for recording drain, then rechecks identity/approval/seals. A unique root stop nonce
binds the exact stopped runtime and native boot to a fresh closed lifecycle state
and durable capture inventory. After all four service processes stop, capture bytes
must remain identical; a changed file is an operator hold. Only the root native
heartbeat is excluded from that inventory. No terminal is invented or rewritten.
Config originals, absence, modes and checksums are retained in a root rollback bank.
Foreign replacement or changed bank rejects. Publication commits durably before
admission resumes; an ambiguous resume holds without stopping a possibly admitted
game. Failed attempts consume the monotonic sequence.

A candidate failing before a healthy closed lifecycle exists **holds for operator
review rather than automatically restoring**: its safe stop proof cannot be obtained.
The fake transaction tests prove rollback when that exact healthy stop barrier exists;
they do not prove recovery of every failed boot. The operator must diagnose and prove
quiescence separately before any further rollback. No force-kill fallback is provided.

## Shared ingress proposal and activation checklist

The minimal shared GUI keeps the existing tailnet HTTPS endpoint and loopback8180
upstream. LAN192.168.0.178:8443 gains HTTPS with exact192.168.0.0/24 access; existing
LAN8180 redirects there. A separately approved IP-SAN certificate/private LAN CA and
client trust are prerequisites, so LAN transport/trust changes need explicit approval.
Both addresses share the same default-Engine/manual-Luna GUI and native backend.
No per-game TLS gate, extra proxy capability, nftables redesign, Funnel, WAN/router
forwarding, public provider/recording/admin route or account authentication is added.
Origins are exact browser cross-site checks; host-local processes are explicitly
trusted and Origin is not an identity credential.

Before activation, assemble final matched artifacts and the Linux self-contained
interpreter/JDK/installed SDK/wheel closure, preserve and hash the original catalog,
produce a fresh exact synthetic qualification/restore/cleanup receipt for the whole
runtime tuple, and verify the actual service identities/units, certificate trust,
backup/storage reserve and all source checks. The renderer produces reviewable text
only. Its isolated systemd CI fixture proves dependency/condition/fake-credential
ordering; it does not stand in for whole-runtime qualification or a live unit test.
No qualification gate may be filled from a string test or the mere existence of code.
Root operator-policy activationApproved and the exact approval receipt remain absent
until the owner separately approves this complete activation diff.
